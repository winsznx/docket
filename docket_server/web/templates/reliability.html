Built for bad internet and restarts.

A clinic's internet drops, servers restart and phones lose signal. Three things keep everyone's place safe when that happens.

  • The desk keeps calling offline

    Every desk action is saved on the device first. If the internet drops, the receptionist keeps calling patients. When the connection comes back, the desk sends what it did and the server checks each action. The server has the final say, and anything it turns down shows up at the desk with the reason.

  • Timers live in the database

    When a patient is called, the moment their {{graceMinutes}} to confirm run out is written to Postgres, and the server acts on it from there. A restart can't lose anyone's place, because the deadline is still in the database when the server comes back.

  • Phones catch up on their own

    A phone that drops off reconnects by itself and loads the line as it is now. While it's reconnecting, the ticket dims and shows the time of its last update, so an old screen never passes for a live one.
