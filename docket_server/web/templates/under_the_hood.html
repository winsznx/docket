Built on Serverpod 4.

One Dart server runs the API, the live updates, the timers and this website. Here's what each Serverpod feature does in Docket.

Endpoints
Every screen talks to the server through typed calls and a generated client.
Streaming methods and session.messages
Tap Call next and every phone in the line moves at once.
Future calls
A missed call re-slots on a deadline stored in the database, so a restart can't lose it. The live app is on Serverpod Cloud's Starter plan, which turns future calls off, so the server runs the same timer rules from a sweep every second. On the Growth plan the same code uses future calls with no change.
ORM, transactions and LockMode.forUpdate
Two desks pressing Call next at the same moment never call the same patient.
Client-side database
The desk keeps calling through an internet outage and syncs when the connection is back.
serverpod_auth_idp
Clinic staff sign in with email.
Web server, Relic routes and FlutterRoute
This site, the app, the ticket's first paint and the PDF posters all come from the same server.
Serverpod Cloud
One command deploys the server with a managed Postgres database.
Insights and health probes
Logs, slow queries and health checks for the live app.
serverpod start
One command runs the server, the database and the app, with the MCP server the coding agent uses.
